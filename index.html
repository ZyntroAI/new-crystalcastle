Production-Grade Pytest Authentication Testing

TL;DR: Use pytest-asyncio, httpx.AsyncClient, ASGITransport, async SQLAlchemy sessions, PostgreSQL transactions, SAVEPOINTs, reusable authentication fixtures, and a DatabaseTestContext that owns the complete test transaction lifecycle.

1. Pytest Authentication Guidelines

Use fixtures for authentication setup

Create reusable fixtures for users, tokens, sessions, and authenticated clients. Keep authentication setup out of individual test bodies.

Never use real credentials

  • Use fake/test users.
  • Generate tokens using the application's token implementation.
  • Keep secrets out of source code, logs, and test output.

Separate authentication from authorization

  • Authentication: Who are you?
  • Authorization: Are you allowed to do this?

Cover important cases

Scenario Expected result
Valid credentials 200 / successful login
Invalid password 401
Unknown user 401
Missing credentials/token 401
Expired/invalid token 401
Insufficient permissions 403
Correct credentials and permissions Success

Security boundaries

  • User A cannot access User B's resources.
  • Normal users cannot access admin endpoints.
  • Revoked credentials are rejected.
  • Expired credentials are rejected.
  • Tampered tokens are rejected.
  • Authentication state does not leak between tests.

3. Transaction Isolation with SAVEPOINT

A simple transaction fixture is insufficient when application code calls session.commit(). Use an outer transaction owned by the test and a nested transaction/SAVEPOINT owned by the application session.

Test fixture └── BEGIN <-- never permanently committed └── SAVEPOINT <-- application works here ├── INSERT ├── UPDATE ├── COMMIT │ └── new SAVEPOINT

When application code executes await session.commit(), the SAVEPOINT is recreated. The outer transaction remains available for final rollback.

At teardown: 

await outer_transaction.rollback()

Everything created during the test is removed.

4. Multiple Database Sessions

When one FastAPI request uses multiple database dependencies, each test session can have its own SAVEPOINT while sharing the same underlying PostgreSQL connection and outer test transaction.

Test │ └── Connection │ └── OUTER TRANSACTION │ ├── Session A │ └── SAVEPOINT A │ ├── INSERT │ ├── COMMIT │ └── SAVEPOINT A' │ └── Session B └── SAVEPOINT B ├── INSERT ├── COMMIT └── SAVEPOINT B'

This provides one final rollback boundary while allowing independent AsyncSession objects.

Important: This pattern assumes the sessions use the same database and underlying connection. If dependencies point to genuinely different databases, each database needs its own connection and outer transaction.

5. Reusable DatabaseTestContext

The reusable context below owns:

  • The database connection.
  • The outer transaction.
  • All test sessions.
  • SAVEPOINT lifecycle.
  • SQLAlchemy transaction listeners.
  • FastAPI dependency overrides.
  • Cleanup and rollback.

tests/conftest.py

from __future__ import annotations

from collections.abc import AsyncGenerator, Callable
from typing import Any

import pytest_asyncio
from fastapi import FastAPI
from httpx import ASGITransport, AsyncClient
from sqlalchemy import event
from sqlalchemy.ext.asyncio import (
    AsyncConnection,
    AsyncEngine,
    AsyncSession,
    create_async_engine,
)

from app.database import Base, get_db, get_reporting_db
from app.main import app


TEST_DATABASE_URL = (
    "postgresql+asyncpg://postgres:postgres@localhost:5432/myapp_test"
)


engine: AsyncEngine = create_async_engine(
    TEST_DATABASE_URL,
    echo=False,
    pool_pre_ping=True,
)


class DatabaseTestContext:
    """Manage test sessions and FastAPI dependency overrides."""

    def __init__(
        self,
        connection: AsyncConnection,
        application: FastAPI,
        dependencies: tuple[Callable[..., Any], ...] = (),
    ) -> None:
        self.connection = connection
        self.application = application
        self.dependencies = dependencies

        self._sessions: list[AsyncSession] = []
        self._overrides: dict[
            Callable[..., Any],
            AsyncSession,
        ] = {}
        self._listeners: dict[
            AsyncSession,
            Callable[..., Any],
        ] = {}
        self._outer_transaction = None

    async def start(self) -> None:
        """Start the test transaction and database dependencies."""
        self._outer_transaction = await self.connection.begin()

        for dependency in self.dependencies:
            self.session_for(dependency)

        await self.initialize()
        self.apply_overrides()

    def session_for(
        self,
        dependency: Callable[..., Any],
    ) -> AsyncSession:
        """Return or create a session for a FastAPI dependency."""
        existing = self._overrides.get(dependency)

        if existing is not None:
            return existing

        session = AsyncSession(
            bind=self.connection,
            expire_on_commit=False,
        )

        self._sessions.append(session)
        self._overrides[dependency] = session

        return session

    async def initialize(self) -> None:
        """Initialize SAVEPOINTs for all registered sessions."""
        for session in self._sessions:
            await session.begin_nested()
            self._install_savepoint_listener(session)

    def _install_savepoint_listener(
        self,
        session: AsyncSession,
    ) -> None:
        sync_session = session.sync_session

        def restart_savepoint(
            session_instance: Any,
            transaction: Any,
        ) -> None:
            if not transaction.nested:
                return

            parent = transaction._parent

            if parent is None or parent.nested:
                return

            if session_instance.is_active:
                session_instance.begin_nested()

        event.listen(
            sync_session,
            "after_transaction_end",
            restart_savepoint,
        )

        self._listeners[session] = restart_savepoint

    def apply_overrides(self) -> None:
        """Install all registered FastAPI dependency overrides."""

        for dependency, session in self._overrides.items():

            async def override(
                session: AsyncSession = session,
            ) -> AsyncGenerator[AsyncSession, None]:
                yield session

            self.application.dependency_overrides[dependency] = override

    def session(
        self,
        dependency: Callable[..., Any],
    ) -> AsyncSession:
        """Get the session associated with a dependency."""
        try:
            return self._overrides[dependency]
        except KeyError as exc:
            raise KeyError(
                f"Dependency {dependency!r} is not registered."
            ) from exc

    async def close(self) -> None:
        """Clean up overrides, sessions, and the outer transaction."""
        self.application.dependency_overrides.clear()

        for session, listener in self._listeners.items():
            event.remove(
                session.sync_session,
                "after_transaction_end",
                listener,
            )

        self._listeners.clear()

        for session in reversed(self._sessions):
            await session.close()

        self._sessions.clear()
        self._overrides.clear()

        if (
            self._outer_transaction is not None
            and self._outer_transaction.is_active
        ):
            await self._outer_transaction.rollback()

        self._outer_transaction = None

8. Testing Application Code That Calls commit()

Production endpoints can safely call await db.commit(). 

@router.post("/users")
async def create_user(
    payload: UserCreate,
    db: AsyncSession = Depends(get_db),
):
    user = User(
        email=payload.email,
        username=payload.username,
        hashed_password=get_password_hash(
            payload.password
        ),
    )

    db.add(user)
    await db.commit()
    await db.refresh(user)

    return user

The test can exercise this endpoint normally: 

@pytest.mark.asyncio
async def test_create_user(
    client: AsyncClient,
    db_session: AsyncSession,
):
    response = await client.post(
        "/users",
        json={
            "email": "new@example.com",
            "username": "new-user",
            "password": "test-password",
        },
    )

    assert response.status_code == 201

    result = await db_session.execute(
        select(User).where(
            User.email == "new@example.com"
        )
    )

    user = result.scalar_one()

    assert user.username == "new-user"

@pytest.mark.asyncio
async def test_create_order_with_multiple_sessions(
    authenticated_client: AsyncClient,
    db_context: DatabaseTestContext,
):
    response = await authenticated_client.post(
        "/orders",
        json={
            "customer_id": 123,
            "total": 49.99,
        },
    )

    assert response.status_code == 200

    db = db_context.session(get_db)
    reporting_db = (
        db_context.session(get_reporting_db)
    )

    order_result = await db.execute(
        select(Order).where(
            Order.customer_id == 123
        )
    )

    order = order_result.scalar_one()

    audit_result = await reporting_db.execute(
        select(AuditLog).where(
            AuditLog.resource_id == order.id
        )
    )

    audit = audit_result.scalar_one()

    assert audit.action == "order.created"

11. Authentication Testing Layers

JWT creation ↓ JWT validation ↓ Current-user dependency ↓ Authentication ↓ Authorization ↓ Protected business logic ↓ Database behavior

Test these layers independently where practical. This prevents every endpoint test from becoming an implicit test of the entire authentication system.

  • JWT creation should be tested for expected claims.
  • JWT validation should reject malformed tokens.
  • Expired JWTs should be rejected.
  • Tokens signed with the wrong key should be rejected.
  • Inactive users should be rejected.
  • Role/scope restrictions should return 403.
  • Protected endpoints should verify authenticated identity.

12. Important Architectural Caveats

Different databases

Do not force genuinely separate databases into one transaction:

Database A └── Connection A └── Transaction A Database B └── Connection B └── Transaction B

Each database requires its own transaction boundary.

Concurrent requests

Do not use a single connection for concurrent production-style request tests. Two simultaneous requests should use separate connections and transactions.

Background tasks

Background tasks that create their own database sessions cannot safely participate in the request's fixture-owned transaction. Test those tasks independently or explicitly control their lifecycle.

Real password hashing

Do not invent a bcrypt hash such as a placeholder test hash if the application expects a real password hash. Use the application's existing get_password_hash() implementation.

Authentication libraries

Avoid reproducing the complete test suite of mature libraries such as JWT or password-hashing libraries. Test your application's integration, configuration, claims, error handling, and security boundaries instead.

14. Final Recommended Architecture

pytest │ ├── pytest-asyncio │ ├── httpx.AsyncClient │ └── ASGITransport │ └── FastAPI application │ ├── DatabaseTestContext │ ├── PostgreSQL connection │ ├── outer transaction │ ├── Session A + SAVEPOINT │ ├── Session B + SAVEPOINT │ ├── Session N + SAVEPOINT │ └── FastAPI dependency overrides │ ├── Authentication fixtures │ ├── test_user │ ├── access_token │ ├── authenticated_client │ ├── admin_user │ └── admin_client │ └── Tests ├── authentication ├── authorization ├── protected endpoints ├── JWT validation ├── roles/scopes └── security boundaries

15. Key Rules

  1. Never use production credentials or secrets in tests.
  2. Use fixtures for users, JWTs, sessions, and authenticated clients.
  3. Test authentication and authorization separately.
  4. Use the application's real JWT and password-hashing functions.
  5. Use PostgreSQL when production uses PostgreSQL.
  6. Use an outer transaction plus SAVEPOINTs when application code calls session.commit().
  7. Give every independent session its own SAVEPOINT.
  8. Share the connection only when sessions logically target the same database and test isolation is desired.
  9. Use separate connections for concurrency tests.
  10. Clear FastAPI dependency overrides during teardown.
  11. Roll back the outer transaction after every test.
  12. Do not allow background sessions to accidentally escape the test transaction model.

# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| main    | :white_check_mark: |
| dev     | :white_check_mark: |
| < 1.0   | :x:                |

> หมายเหตุ: โปรเจกต์นี้ยังอยู่ในช่วง Private/Experimental ดังนั้นเฉพาะ branch `main` และ `dev` ที่ได้รับการสนับสนุนด้านความปลอดภัย

---

## Reporting a Vulnerability

เรายินดีเป็นอย่างยิ่งหากคุณช่วยรายงานช่องโหว่ความปลอดภัยที่ค้นพบ เช่น:
- Cross-Site Scripting (XSS)
- การรั่วไหลของข้อมูลส่วนตัว (PII)
- การรั่วไหลของ API Keys / Secrets
- SQL Injection
- Remote Code Execution (RCE)

### ช่องทางการรายงาน

**🔒 วิธีที่แนะนำ:** เปิด [GitHub Security Advisory](https://github.com/Zyntro-Media-AI/crystalcastle-dev/security/advisories/new)  
**📧 อีเมล:** security@zyntro.ai (หรืออีเมลที่คุณใช้งานจริง)

กรุณาระบุรายละเอียดต่อไปนี้:
1. คำอธิบายช่องโหว่
2. ขั้นตอนการ reproduce
3. Impact / ระดับความรุนแรงที่ประเมินไว้
4. Proof of Concept (ถ้ามี)

### เวลาตอบกลับ

| ขั้นตอน | ระยะเวลา |
|---|---|
| ยืนยันการได้รับรายงาน | ภายใน 72 ชั่วโมง |
| ประเมินความรุนแรง | ภายใน 7 วัน |
| แจ้งความคืบหน้า | ทุก ๆ 7 วัน จนกว่าจะแก้ไขเสร็จ |
| เปิดเผยต่อสาธารณะ | หลังจากแก้ไขเสร็จสมบูรณ์ (Coordinated Disclosure) |

## Out of Scope

รายงานต่อไปนี้ **ไม่ถือว่าเป็นช่องโหว่ความปลอดภัย**:

| หัวข้อ | เหตุผล |
|---|---|
| Rate limiting | ยังไม่ได้ implement ในระบบปัจจุบัน |
| ปัญหาที่ต้องใช้ physical access | ไม่สามารถ exploit ผ่านระยะไกลได้ |
| Social engineering / Phishing | นอกเหนือขอบเขตของโค้ดและระบบ |
| ช่องโหว่ในส่วนของ third-party dependencies ที่ไม่ได้ใช้งานจริง | กรุณารายงานต่อผู้พัฒนาโดยตรง |
| การทดสอบบน environment ที่ไม่ใช่ของเรา | กรุณาทดสอบบน dev/staging ที่เรากำหนดเท่านั้น |

## Safe Harbor

เราสนับสนุนการทดสอบความปลอดภัยที่มีจริยธรรม หากคุณ:
- ปฏิบัติตามนโยบายนี้
- ไม่ทำลายข้อมูลของผู้ใช้รายอื่น
- ไม่ exploit ช่องโหว่เพื่อหาประโยชน์ส่วนตัว

เราจะไม่ดำเนินคดีทางกฎหมายต่อคุณ

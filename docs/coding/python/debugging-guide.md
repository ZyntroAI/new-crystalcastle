# 🔍 คู่มือการดีบักโค้ด Python

> ขั้นตอนและเครื่องมือค้นหาและแก้ไขข้อผิดพลาดอย่างเป็นระบบ

---

## 📌 ขั้นตอนพื้นฐานก่อนเริ่มดีบัก

1. **เข้าใจปัญหา** — อ่านข้อความแจ้งเตือนให้ชัดเจน รู้ว่าระบบบอกอะไร
2. **ทำซ้ำได้เสมอ** — หาวิธีทำให้ปัญหาเกิดขึ้นอีกครั้งตามขั้นตอนเดิม
3. **แยกส่วน** — ลดขอบเขตให้เล็กที่สุด เหลือแค่ส่วนที่ทำให้เกิดปัญหา
4. **ตรวจสอบสมมติฐาน** — อย่ามั่นใจว่าสิ่งที่คิดว่าถูกต้อง อาจไม่ถูกต้องจริง
5. **บันทึกสิ่งที่พบ** — จดสิ่งที่ลองและผลลัพธ์ เพื่อไม่ให้ทำซ้ำ

---

## 🖨️ ระดับ 1: พิมพ์ค่าดู (Print Debugging)

วิธีพื้นฐานที่สุด — ใช้เมื่อปัญหาไม่ซับซ้อน

```python
def calculate_total(price, quantity):
    print(f"[DEBUG] price = {price}, quantity = {quantity}")
    total = price * quantity
    print(f"[DEBUG] total = {total}")
    return total
 
 
⚠️ ข้อจำกัด: ไม่เหมาะกับโค้ดซับซ้อน ล้างทิ้งย่อยาก และรบกวนการทำงานปกติ
 
 
 
🐛 ระดับ 2: ใช้ pdb — Debugger ในตัว
 
คำสั่งพื้นฐาน pdb
 
คำสั่ง ทำอะไร 
 n  (next) ข้ามไปบรรทัดถัดไป ไม่เข้าฟังก์ชัน 
 s  (step) เข้าไปดูภายในฟังก์ชันถัดไป 
 l  (list) แสดงโค้ดบริเวณจุดปัจจุบัน 
 p <ชื่อตัวแปร>  แสดงค่าของตัวแปร 
 b <บรรทัด>  ตั้งจุดพักที่บรรทัดที่ระบุ 
 c  (continue) รันต่อจนจบหรือถึงจุดพักถัดไป 
 q  (quit) ออกจาก debugger 
 bt  แสดงลำดับการเรียกใช้ (stack trace) 
 
วิธีใช้
 
python  
import pdb

def process_data(data):
    pdb.set_trace()  # โปรแกรมหยุดที่นี่
    result = transform(data)
    return result
 
 
💡 Python 3.7+ มี  breakpoint()  ใช้แทน  pdb.set_trace()  ได้เลยครับ
 
 
 
📝 ระดับ 3: บันทึกเหตุการณ์ด้วย logging
 
python  
import logging

# ตั้งค่าครั้งเดียวที่ต้นโปรแกรม
logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("app.log"),
        logging.StreamHandler()  # แสดงหน้าจอด้วย
    ]
)

# ใช้งานในโค้ด
logging.debug("ค่าตัวแปร: %s", user_id)  # ข้อมูลเชิงลึกสำหรับนักพัฒนา
logging.info("เริ่มทำงาน")                 # เหตุการณ์ทั่วไป
logging.warning("ใกล้หมดเวลาเชื่อมต่อ")    # ไม่ผิดพลาด แต่อาจเกิดปัญหา
logging.error("บันทึกข้อมูลไม่ได้")         # ล้มเหลวในงานหนึ่ง
logging.critical("ระบบหยุดทำงาน")          # ร้ายแรงต้องแก้ทันที
 
 
✅ ปิด debug log ได้ง่ายโดยเปลี่ยน  level=logging.INFO  — ไม่ต้องลบโค้ดทิ้ง
 
 
 
🧪 ระดับ 4: ตรวจสอบด้วยตัวเองอย่างเป็นระบบ
 
เช็คลิสต์ก่อนถามคนอื่น
 
อ่านข้อความ Error ทั้งหมดแล้วหรือยัง?
ค้นหาข้อความ Error ใน Google/Documentation แล้วหรือยัง?
ปัญหาเกิดที่บรรทัดไหน ตรงไหน?
ตัวแปรมีค่าถูกต้องไหมก่อนใช้งาน?
เงื่อนไข if/else ทำตามที่คิดไหม?
ลองรันซ้ำอีกครั้งแล้วหรือยัง?
เปลี่ยนแปลงอะไรก่อนที่มันจะพัง?
 
ข้อความผิดพลาดที่พบบ่อย
 
ข้อความ สาเหตุที่เป็นไปได้ สิ่งที่ต้องตรวจ 
 NameError  ใช้ชื่อตัวแปร/ฟังก์ชันที่ยังไม่ได้สร้าง พิมพ์ถูกไหม, ประกาศก่อนใช้ไหม 
 IndentationError  เยื้องผิดระดับ ดูช่องว่าง/แท็บให้ตรงกัน 
 IndexError  เข้าถึงตำแหน่งที่ไม่มีในรายการ ความยาวลิสต์, เริ่มที่ 0 ไม่ใช่ 1 
 KeyError  เรียก key ที่ไม่มีใน dict เช็คด้วย  .get()  หรือ  in  ก่อนเข้าถึง 
 TypeError  ชนิดข้อมูลไม่ตรงกับที่คาดหวัง ตรวจสอบประเภทด้วย  type()  
 ValueError  ชนิดถูก แต่ค่าไม่อยู่ในช่วงที่ยอมรับ ตรวจสอบค่าก่อนส่ง 
 AttributeError  เรียกเมธอด/คุณสมบัติที่ไม่มีในอ็อบเจกต์ ตรวจสอบประเภทอ็อบเจกต์ 
 ModuleNotFoundError  ยังไม่ได้ติดตั้ง หรือพิมพ์ชื่อผิด ติดตั้งด้วย pip, ตรวจสอบชื่อ 
 
 
 
🛠️ เครื่องมือช่วยดีบักเพิ่มเติม
 
เครื่องมือ ใช้ทำอะไร ติดตั้ง 
 icecream  พิมพ์ค่าตัวแปรได้สวยและมีชื่ออัตโนมัติ  pip install icecream  →  ic(var)  
 snoop  ดูทุกบรรทัดที่รัน และค่าทุกตัวแปร  pip install snoop  → แตะ decorator ที่ฟังก์ชัน 
 pudb  Debugger แบบ UI บนหน้าจอ  pip install pudb  →  import pudb; pudb.set_trace()  
 traceback  แสดงรายละเอียดข้อผิดพลาดแบบละเอียด มีในตัว —  import traceback; traceback.print_exc()

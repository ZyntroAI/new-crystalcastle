# ⚡ คู่มือปรับปรุงประสิทธิภาพ Python

> กฎสำคัญ: **อย่าปรับปรุงก่อนที่จะรู้ว่าต้องปรับ** — วัดผลเสมอ ก่อนแก้ไข ✅

---

## 📏 1. วัดผลก่อนทุกครั้ง

### ⏱️ วัดเวลารันโค้ด
```python
import time

start = time.perf_counter()
result = process_data(large_dataset)
end = time.perf_counter()
print(f"ใช้เวลา: {end - start:.4f} วินาที")
 
 
📊 ค้นหาส่วนที่ช้าที่สุดด้วย cProfile
 
bash  
# รันและดูว่าส่วนไหนใช้เวลามากที่สุด
python -m cProfile -s cumulative your_script.py
 
 
💡 กฎทอง: อย่าเดา — วัดผลเสมอ ส่วนใหญ่โค้ดส่วนเล็กๆ เป็นสาเหตุของปัญหาความเร็ว 80/20 Rule
 
 
 
🚀 2. เทคนิคพื้นฐานที่ช่วยได้มาก
 
✅ ใช้ชนิดข้อมูลที่เหมาะสม
 
สิ่งที่ต้องการทำ ใช้สิ่งนี้ หลีกเลี่ยง เหตุผล 
ตรวจสอบว่ามีอยู่หรือไม่  set  หรือ  dict   list  ค้นหา O(1) แทน O(n) 
รวบรวมค่าเรียงลำดับ  deque  จาก  collections   list  เมื่อต้องเพิ่มทั้งสองด้าน เพิ่ม/ลบที่ปลายได้ O(1) 
จำนวนนับ  Counter  ลูปนับเอง ปรับปรุงแล้วและสะดวกกว่า 
ค่าเริ่มต้นอัตโนมัติ  defaultdict  ตรวจสอบ key ทุกครั้ง ลดโค้ดและลดข้อผิดพลาด 
 
✅ หลีกเลี่ยงการทำซ้ำในลูป
 
python  
# ❌ ไม่ดี — คำนวณซ้ำทุกรอบ
for item in items:
    result = expensive_function(item)  # ถ้าค่าเหมือนเดิมทุกครั้ง

# ✅ ดี — คำนวณครั้งเดียว แล้วนำมาใช้ซ้ำ
cache_value = expensive_function()
for item in items:
    result = cache_value
 
 
✅ ใช้ Comprehension แทนลูป
 
python  
# ❌ ช้ากว่า
squares = []
for num in numbers:
    squares.append(num * num)

# ✅ เร็วกว่าและกระชับกว่า
squares = [num * num for num in numbers]
 
 
✅ รวมสตริงด้วย .join() ไม่ใช่ +=
 
python  
# ❌ ช้ามาก เมื่อมีรายการเยอะ
result = ""
for part in parts:
    result += part

# ✅ ถูกวิธี
result = "".join(parts)
 
 
 
 
🧠 3. ใช้โมดูลมาตรฐาน — เร็วที่สุดเพราะเขียนด้วย C
 
ปัญหา ใช้โมดูลในตัว 
คณิตศาสตร์  math ,  statistics  — เร็วกว่าเขียนเอง 
การประมวลผลไฟล์/เส้นทาง  pathlib  — จัดการได้มีประสิทธิภาพและถูกต้อง 
ข้อมูลแบบมีโครงสร้าง  json ,  csv  — มาตรฐานและผ่านการทดสอบแล้ว 
การบีบอัด/ถอดรหัส  zlib ,  base64  — เร็วและปลอดภัย 
การประมวลผลข้อมูลไบนารี  struct  — อ่าน/เขียนข้อมูลไบนารีได้มีประสิทธิภาพ 
 
 
 
💾 4. จัดการหน่วยความจำ
 
✅ ใช้ Generator เมื่อไม่ต้องการเก็บทั้งหมด
 
python  
# ❌ สร้างรายการเต็มหมด — ใช้หน่วยความจำมาก
def get_numbers():
    return [x for x in range(1_000_000)]

# ✅ สร้างทีละค่า — ใช้หน่วยความจำคงที่ ไม่ขยายตามขนาด
def get_numbers():
    for x in range(1_000_000):
        yield x
 
 
✅ ประมวลผลทีละส่วน ไม่โหลดทั้งไฟล์
 
python  
# ❌ อ่านทั้งหมดลงหน่วยความจำ
with open("huge_file.txt") as f:
    lines = f.readlines()

# ✅ อ่านทีละบรรทัด
with open("huge_file.txt") as f:
    for line in f:
        process(line)
 
 
 
 
⚡ 5. เมื่อต้องเร็วขึ้นอีก — เลือกเครื่องมือที่เหมาะสม
 
สถานการณ์ ทางเลือก ข้อสังเกต 
คำนวณเชิงตัวเลข/เมทริกซ์ NumPy — เก็บข้อมูลต่อเนื่องในหน่วยความจำ เร็ว 10–100 เท่า ต้องเรียนรู้ไวยากรณ์ใหม่ 
ตารางข้อมูล/วิเคราะห์ข้อมูล Pandas — ประมวลผลแบบ Vectorized เร็วกว่าลูปมาก ต้องจัดการชนิดข้อมูลให้ถูกต้อง 
ฟังก์ชันที่รันบ่อยมาก Cython / Numba — แปลงเป็นโค้ดที่คอมไพล์ ต้องระมาระบุชนิดข้อมูลอย่างชัดเจน 
งานที่ทำทีละอันเยอะๆ concurrent.futures — รันขนานกันได้หลายงาน ระวังเรื่องการแชร์ตัวแปรระหว่างเธรด 
 
⚠️ ข้อควรระวัง: อย่าเริ่มด้วยสิ่งเหล่านี้ — ปรับโค้ดธรรมดาให้ดีก่อนเสมอ ส่วนใหญ่แค่เลือกชนิดข้อมูลถูกก็เพียงพอแล้วครับ

# 💬 คอลเลกชันพร้อมท์สำหรับนักพัฒนา

> ชุดพร้อมท์สำเร็จ — คัดลอก ใส่รายละเอียด แล้วใช้งานได้ทันที

---

## 🐍 Python

### ✅ เขียนโค้ดใหม่
> "เขียนสคริปต์ Python สำหรับ [งานที่ต้องการ] ให้มีโครงสร้างชัดเจน ตามหลัก PEP8 มีคอมเมนต์อธิบาย และจัดการข้อผิดพลาดด้วย try-except ด้วยครับ"

### ✅ อธิบายและอ่านโค้ด
> "อธิบายโค้ด Python นี้ทีละส่วน ทีละบรรทัดถ้าจำเป็น บอกว่าแต่ละส่วนทำหน้าที่อะไร และมีจุดที่สามารถปรับปรุงได้ไหม"
>
> *วางโค้ดต่อท้ายข้อความ*

### ✅ แก้ไขปัญหา
> "สคริปต์นี้เกิดข้อผิดพลาดตามข้อความด้านล่าง ช่วยบอกสาเหตุและแก้ไขให้หน่อยครับ: [วางข้อความ Error Traceback ที่นี่]"

### ✅ ปรับปรุงประสิทธิภาพ
> "ช่วยตรวจสอบโค้ดนี้ว่ามีจุดไหนที่ทำให้ทำงานช้าหรือใช้หน่วยความจำมากไหม และแนะนำวิธีปรับปรุงให้เร็วขึ้นพร้อมเหตุผลครับ"

---

## 🟨 JavaScript + 🔷 TypeScript

### ✅ เขียนฟังก์ชันใหม่
> "เขียนฟังก์ชัน JavaScript ที่ทำหน้าที่ [รายละเอียด] ใช้ ES6+ syntax จัดการ edge case ต่างๆ ให้ครบถ้วน และเขียน JSDoc อธิบายการใช้งานด้วยครับ"

### ✅ แก้ Type Error
> "โค้ด TypeScript นี้แจ้ง error ดังนี้: [วางข้อความที่นี่] ช่วยแก้ไขและอธิบายสาเหตุที่เกิดขึ้นพร้อมวิธีป้องกันในอนาคตด้วยครับ"

### ✅ แปลง JS → TS
> "แปลงโค้ด JavaScript นี้ให้เป็น TypeScript ที่สมบูรณ์ กำหนด type ให้ถูกต้องทั้งหมด ใช้ interface/type ที่เหมาะสม และรักษาการทำงานเหมือนเดิมครับ"

---

## ⚛️ React / JSX / TSX

### ✅ สร้าง Component ใหม่
> "สร้าง React Function Component ด้วย TypeScript (TSX) สำหรับ [ชื่อ/หน้าที่] ใช้ Hooks ตามมาตรฐาน ออกแบบ Props interface ให้ชัดเจน และจัดการกรณีที่ค่าเป็น undefined ได้ถูกต้องครับ"

### ✅ ปรับปรุง Component
> "ตรวจสอบ Component นี้: [วางโค้ดที่นี่] ดูว่ามีปัญหาเรื่องการ re-render หรือการจัดการ state ไหม และแนะนำวิธีปรับปรุงให้ดีขึ้นครับ"

### ✅ แก้ปัญหา useEffect
> "Component นี้ทำงานไม่ถูกต้องตามที่คาดหวัง ดูเหมือน useEffect ทำงานซ้ำหรือไม่ทำงาน ช่วยวิเคราะห์และแก้ไขให้ถูกต้อง พร้อมอธิบายเหตุผลครับ"

---

## 🟦 Go (Golang)

### ✅ เขียนฟังก์ชัน/แพ็กเกจ
> "เขียนฟังก์ชัน Go ที่ทำหน้าที่ [รายละเอียด] ปฏิบัติตามมาตรฐาน Go, ตรวจสอบและคืนค่า error ทุกจุดที่จำเป็น พร้อมเขียนตัวอย่างการใช้งานและ comment อธิบายครับ"

### ✅ ตรวจสอบความปลอดภัย/ข้อผิดพลาด
> "ตรวจสอบโค้ด Go นี้อย่างละเอียด: [วางโค้ดที่นี่] บอกจุดที่ต้องระวัง ปัญหาความปลอดภัย การจัดการ error ที่อาจขาดหายไป และแนะนำการปรับปรุงตามหลัก Go best practice ครับ"

### ✅ อธิบาย Goroutine / Channel
> "อธิบายการทำงานของโค้ดส่วนนี้ที่ใช้ Goroutine และ Channel บอกตรรกะการทำงาน ลำดับที่อาจเกิดขึ้น และมีความเสี่ยงเกิด deadlock หรือไม่ พร้อมเหตุผลครับ"

---

## 🐚 Shell / Bash

### ✅ เขียนสคริปต์
> "เขียนสคริปต์ Bash สำหรับ [วัตถุประสงค์] ตรวจสอบความถูกต้องของ input แจ้งเตือนเมื่อสำเร็จ/ล้มเหลว ใส่คอมเมนต์อธิบาย และเตือนถ้าคำสั่งใดมีความเสี่ยงครับ"

### ✅ ตรวจสอบก่อนรัน
> "ตรวจสอบสคริปต์นี้ก่อนที่จะรันจริง: [วางโค้ดที่นี่] มีคำสั่งไหนที่อันตรายหรืออาจทำให้ข้อมูลเสียหายไหม แจ้งให้ทราบอย่างชัดเจนและเสนอทางเลือกที่ปลอดภัยกว่าครับ"

### ✅ แก้สคริปต์ที่ไม่ทำงาน
> "สคริปต์นี้รันแล้วไม่ได้ผลลัพธ์ตามที่ต้องการ: [วางโค้ดที่นี่] ช่วยหาสาเหตุและแก้ไขให้ถูกต้อง พร้อมคำอธิบายครับ"

---

## 🧪 การทดสอบ

### ✅ เขียน Unit Test
> "เขียนชุดทดสอบสำหรับฟังก์ชันนี้ ใช้ [ไลบรารี: pytest/Jest/Go Test] ครอบคลุมกรณีปกติ, กรณีข้อมูลไม่ถูกต้อง, และ edge case ที่สำคัญ เขียนให้อ่านง่าย พร้อมคำอธิบายว่าแต่ละเคสทดสอบอะไรครับ"

### ✅ เขียน Integration Test / API Test
> "เขียนการทดสอบสำหรับ API endpoint: [ระบุ URL/Method] ครอบคลุม: ข้อมูลถูกต้อง, ข้อมูลขาดหาย, สิทธิ์เข้าใช้, และกรณีไม่พบข้อมูล ระบุค่าที่คาดหวังให้ชัดเจนครับ"

### ✅ ค้นหาจุดที่ขาดการทดสอบ
> "ตรวจสอบโค้ดนี้ บอกว่าส่วนไหนยังขาดการทดสอบ หรือมีความเสี่ยงที่อาจเกิดข้อผิดพลาดเมื่อนำไปใช้งานจริง แนะนำว่าควรเพิ่มเคสทดสอบอะไรบ้าง พร้อมเหตุผลครับ"

---

## 🚀 การปรับใช้งาน

### ✅ เขียนสคริปต์ปรับใช้
> "เขียนสคริปต์สำหรับปรับใช้แอปพลิเคชัน [ระบุภาษา/แพลตฟอร์ม] ขึ้นเซิร์ฟเวอร์ [ระบุ] แบ่งขั้นตอนชัดเจน ตรวจสอบขั้นตอนก่อนปรับใช้ และแจ้งผลสำเร็จ/ล้มเหลวอย่างชัดเจนครับ"

### ✅ ตรวจสอบก่อนปรับใช้
> "รายการตรวจสอบก่อนนำเข้าสู่ระบบจริง: ช่วยระบุสิ่งที่ต้องตรวจสอบทั้งหมด — ตัวแปรสภาพแวดล้อม, คีย์ความลับ, การสำรองข้อมูล, เวอร์ชัน, การย้อนกลับเมื่อเกิดปัญหา จัดเป็นเช็คลิสต์ที่ทำตามได้ครับ"

---

## 🔧 แก้ปัญหาเฉพาะจุด

### ✅ วิเคราะห์สาเหตุ
> "ระบบแจ้งข้อผิดพลาดดังนี้:
[วางข้อความ Error/Log ที่นี่]
สภาพแวดล้อม: [ระบุระบบ/เวอร์ชัน]
สิ่งที่เพิ่งทำก่อนเกิดปัญหา: [รายละเอียด]
ช่วยวิเคราะห์สาเหตุที่เป็นไปได้ เรียงลำดับจากความเป็นไปได้สูงไปต่ำ และเสนอวิธีแก้ไขทีละขั้นตอนครับ"

---

## 🔌 การจัดการ API

### ✅ ออกแบบ API Spec
> "ออกแบบ API สำหรับ [วัตถุประสงค์] ระบุ: Endpoint, Method, Request Body, Response, Status Code ที่คืน, สิทธิ์ที่ต้องการ และตัวอย่างการเรียกใช้ จัดรูปแบบตามมาตรฐาน OpenAPI ให้ครบถ้วนครับ"

### ✅ จัดการ Error Response
> "กำหนดรูปแบบข้อความแจ้งเตือนข้อผิดพลาดที่เป็นมาตรฐานสำหรับทุก API มีโครงสร้างที่ชัดเจน แยกแยะประเภทปัญหาได้ และให้ข้อมูลที่ช่วยแก้ไขปัญหาโดยไม่เปิดเผยข้อมูลสำคัญของระบบครับ"

---

## 🔑 การหมุนเวียน Token

### ✅ ออกแบบระบบหมุนเวียน Token
> "ออกแบบระบบจัดการ Token/API Key ที่ปลอดภัย ครอบคลุม: การสร้าง, การจัดเก็บที่ปลอดภัย, ระยะเวลาใช้งาน, การหมุนเวียนโดยอัตโนมัติโดยไม่ทำให้ระบบหยุดทำงาน, การเพิกถอนทันทีเมื่อจำเป็น, และการแจ้งเตือนเมื่อใกล้ถึงกำหนดหมดอายุ พร้อมแผนผังภาพรวมครับ"

---

## 🧠 พร้อมท์อเนกประสงค์

### ✅ อธิบายเหมือนคนเริ่มต้น
> "อธิบายแนวคิดเรื่อง [หัวข้อ] ให้เข้าใจง่าย เหมือนผมเพิ่งเริ่มเรียน ไม่ต้องใช้ศัพท์ยาก ถ้าจำเป็นให้เปรียบเทียบ และยกตัวอย่างโค้ดสั้นๆ ประกอบครับ"

### ✅ ตรวจสอบและปรับปรุง
> "นี่คือโค้ดของผมครับ:
[วางโค้ดที่นี่]
ช่วยตรวจสอบ:
✅ ความถูกต้องและตรรกะ
✅ รูปแบบและความอ่านง่าย
✅ ประสิทธิภาพ
✅ ความปลอดภัย
และแนะนำสิ่งที่ควรแก้ไขพร้อมเหตุผลครับ"

### ✅ แปลงภาษา
> "แปลงโค้ดจาก [ภาษาเดิม] เป็น [ภาษาเป้าหมาย] ให้ทำงานเหมือนเดิมทุกประการ รักษาโครงสร้างและชื่อตัวแปรเดิมให้มากที่สุด และใส่คอมเมนต์อธิบายจุดที่แตกต่างกันครับ"

schedule:

`
• ใช้ตรวจสอบและอัปเดต dependency ของ npm และ GitHub Actions
• ตั้งเวลาเป็น weekly เพื่อไม่ให้ PR ล้นเกินไป

📄 ตัวอย่าง codeql.yml
`yaml
name: "CodeQL"

on:
push:
branches: [ "main" ]
pull_request:
branches: [ "main" ]
schedule:
- cron: '0 0 0' # weekly scan

jobs:
analyze:
name: Analyze
runs-on: ubuntu-latest
permissions:
actions: read
contents: read
security-events: write

strategy:
matrix:
language: [ 'javascript', 'python' ]

steps:
- name: Checkout repository
uses: actions/checkout@v4

- name: Initialize CodeQL
uses: github/codeql-action/init@v3
with:
languages: ${{ matrix.language }}

- name: Perform CodeQL Analysis
uses: github/codeql-action/analyze@v3
`
• สแกนทุกครั้งที่มี push หรือ pullrequest
• ใช้ matrix strategy เพื่อรองรับหลายภาษา เช่น JavaScript และ Python
• Weekly scheduled scan เพื่อจับช่องโหว่ที่เกิดจาก dependency ใหม่

• ทำงานทุกครั้งที่มี pull_request ไปยัง branch main

ครับ ✨ มาดูตัวอย่าง security.yml ที่ทำหน้าที่ “รวมผลลัพธ์” จาก workflow ต่าง ๆ และ enforce merge protection ได้เลย

───

📄 ตัวอย่าง security.yml
`yaml
name: "Security Gate"

on:
pull_request:
branches: [ "main" ]

jobs:
security-gate:
runs-on: ubuntu-latest
needs: [lint, test, dependency-review, secret-scan, codeql]
steps:
- name: Checkout repository
uses: actions/checkout@v4

- name: Aggregate Security Results
run: |
echo "Collecting results from all security jobs..."
# ที่นี่สามารถเพิ่ม script ตรวจสอบผลลัพธ์จาก jobs อื่น ๆ
# เช่น parse SARIF จาก CodeQL, ตรวจสอบ secret scan, dependency review
# แล้วสรุปเป็น pass/fail

- name: Enforce Merge Protection
run: |
echo "Failing pipeline if security checks not passed"
# exit 1 ถ้ามีผลลัพธ์ไม่ผ่าน
`

───

🔑 แนวคิดของ security.yml
• ใช้ needs เพื่อบังคับว่า job นี้จะรันหลังจาก workflow อื่น ๆ เช่น lint, unit test, dependency-review, secret-scan, และ codeql
• รวมผลลัพธ์ทั้งหมด → ถ้าเจอช่องโหว่หรือ secret ที่รั่วไหล ให้ pipeline fail
• ใช้ร่วมกับ branch protection rules เพื่อบังคับว่า PR จะ merge ได้ก็ต่อเมื่อ security checks ผ่านทั้งหมด

───

📊 ภาพรวม Security Pipeline
1. Pull Request → trigger workflows
2. Lint + Unit Test → ตรวจสอบคุณภาพโค้ด
3. Dependency Review + Secret Scan + CodeQL → ตรวจสอบช่องโหว่และ secret
4. Security Gate (security.yml) → รวมผลลัพธ์และ enforce policy
5. Merge Protection → ป้องกันการ merge โค้ดที่ไม่ปลอดภัย

───

📄 ตัวอย่าง Branch Protection Rules (สำหรับ branch main)
• Require pull request reviews → ต้องมี reviewer อย่างน้อย 1–2 คน (ตามที่กำหนดใน CODEOWNERS)
• Require status checks to pass before merging → ต้องผ่าน workflow ทั้งหมด เช่น ci.yml, dependency-review.yml, secret-scan.yml, codeql.yml, และ security.yml
• Require signed commits → บังคับให้ commit ต้องมีการเซ็นดิจิทัล
• Require linear history → ป้องกัน merge commit ที่ซับซ้อน
• Restrict who can push to matching branches → จำกัดสิทธิ์ push เฉพาะทีมที่กำหนด เช่น @repo-admins
• Require conversation resolution before merging → ต้องเคลียร์ทุก comment ใน PR ก่อน merge

───

🔑 แนวคิด
• Branch Protection คือ “ด่านสุดท้าย” ที่บังคับให้ทุก PR ต้องผ่าน security pipeline และ review จาก CODEOWNERS
• เมื่อรวมกับไฟล์ที่คุณตั้งไว้ (SECURITY.md, dependabot.yml, codeql.yml, secret-scan.yml, dependency-review.yml, security.yml, CODEOWNERS) → จะได้ระบบที่ครบทั้ง policy, automation, และ enforcement

 นี่คือตัวอย่าง workflow สำหรับ auto‑labeling security issues ด้วย GitHub Actions เพื่อให้ทุก issue ที่เกี่ยวข้องกับ security ถูกติด label อัตโนมัติ

───

📄 ตัวอย่าง .github/workflows/auto-label-security.yml
`yaml
name: "Auto Label Security Issues"

on:
issues:
types: [opened, edited]

jobs:
auto-label:
runs-on: ubuntu-latest
steps:
- name: Apply Security Label
uses: actions/github-script@v7
with:
script: |
const keywords = ["security", "vulnerability", "exploit", "leak", "XSS", "SQLi"];
const issueTitle = context.payload.issue.title.toLowerCase();
const issueBody = context.payload.issue.body.toLowerCase();

if (keywords.some(word => issueTitle.includes(word) || issueBody.includes(word))) {
github.rest.issues.addLabels({
issue_number: context.payload.issue.number,
owner: context.repo.owner,
repo: context.repo.repo,
labels: ["security"]
});
}
`

───

🔑 แนวคิด
• Trigger ทุกครั้งที่มีการ เปิดหรือแก้ไข issue
• ตรวจสอบ keywords เช่น security, vulnerability, exploit, XSS, SQLi
• ถ้าพบ → ติด label security อัตโนมัติ
• ทำให้ทีม security-team เห็น issue ได้ทันทีโดยไม่ต้องรอ manual labeling

🔐 Best Practices: Auto Grants Read/Write/Edit

1. Principle of Least Privilege
• ให้สิทธิ์ Read เป็นค่าเริ่มต้นสำหรับทุกคน
• ให้สิทธิ์ Write/Edit เฉพาะทีมที่ต้องแก้ไขโค้ดจริง ๆ
• ให้สิทธิ์ Admin เฉพาะเจ้าของ repo หรือทีม DevOps ที่ดูแล workflow

───

2. Role-based Access Control
• Developers → Write (push branches, create PR)
• Reviewers (CODEOWNERS) → Write + Review (approve PR)
• Security Team → Write + Manage Issues (triage vulnerabilities)
• Ops/Admins → Admin (manage settings, workflows, secrets)

───

3. Branch Protection Rules
• Require PR review จาก CODEOWNERS ก่อน merge
• Require status checks (CI/CD, security scans) ผ่านก่อน merge
• Restrict direct push → เฉพาะ Admin เท่านั้น

───

4. Fine-grained Personal Access Tokens
• ใช้ token ที่กำหนด scope ชัดเจน เช่น read-only สำหรับ CI/CD
• ห้ามใช้ classic PAT ที่มีสิทธิ์กว้างเกินไป

───

5. GitHub Actions Permissions
ใน workflow (.github/workflows/*.yml) กำหนดสิทธิ์ให้แคบที่สุด เช่น:
yaml permissions: actions: read contents: read security-events: write
• ไม่เปิดสิทธิ์ write-all โดยไม่จำเป็น
• ให้สิทธิ์เฉพาะที่ workflow ต้องใช้จริง ๆ

───

6. Audit & Monitoring
• เปิดใช้งาน Dependabot alerts และ Code scanning alerts
• ใช้ Security Dashboard เพื่อติดตามว่าใครทำอะไรบ้าง
• ตรวจสอบสิทธิ์ทีมทุกไตรมาส → ลดสิทธิ์ที่ไม่จำเป็น

───

📊 สรุป
• Read → ค่าเริ่มต้นสำหรับทุกคน
• Write/Edit → เฉพาะทีม dev และ reviewer ที่กำหนดใน CODEOWNERS
• Admin → เฉพาะเจ้าของ repo และทีม Ops
• ใช้ workflow permissions และ branch protection เพื่อ enforce

• SECURITY.md → ระบุขั้นตอนการรายงานช่องโหว่, supported versions, contact
• CODEOWNERS → กำหนด reviewer สำหรับไฟล์สำคัญ (workflow, security, tests)

───

2. Automation Workflows
• ci.yml → Lint + Unit Tests
• dependabot.yml → อัปเดต dependency อัตโนมัติ
• secret-scan.yml → ตรวจจับ secret/credential รั่วไหล
• dependency-review.yml → ตรวจสอบ package ก่อน merge
• codeql.yml → Static analysis หาช่องโหว่ในโค้ด
• security.yml → รวมผลลัพธ์ทั้งหมดและ enforce merge protection

───

3. Permissions Hardening
• ใช้ Principle of Least Privilege → Read เป็นค่า default, Write เฉพาะที่จำเป็น
• Workflow กำหนด permissions เช่น: 
◦ ci.yml → actions: read, contents: read, pull-requests: write
◦ codeql.yml → actions: read, contents: read, security-events: write
◦ secret-scan.yml → actions: read, contents: read, security-events: write
◦ dependency-review.yml → actions: read, contents: read, pull-requests: write
◦ security.yml → actions: read, contents: read, security-events: write, pull-requests: write

───

4. Branch Protection
• Require PR review จาก CODEOWNERS
• Require status checks ผ่านทุก workflow
• Require signed commits
• Restrict direct push → เฉพาะ Admin เท่านั้น

───

5. Monitoring & Dashboard
• ใช้ GitHub Project Board → To Triage / In Progress / In Review / Resolved
• Metrics → Dependabot Updates, Secret Scans, CodeQL Alerts, Passed Checks
• Auto-label workflow → ติด label “security” อัตโนมัติใน issue

───

6. Incident Response
• ISSUE_TEMPLATE/security.md → สำหรับรายงานช่องโหว่
• Workflow auto-assign → ส่ง issue ไปยังทีม security
• Audit log → บันทึกการแก้ไขและการ triage

───

7. Continuous Improvement
• Review policy/workflow ทุกไตรมาส
• Training ทีม dev เรื่อง secure coding
• Compliance check → เก็บ log สำหรับ audit ภายนอก

───

📊 สรุป
• Policy + Ownership → SECURITY.md + CODEOWNERS
• Automation + Enforcement → Workflow + Branch Protection
• Monitoring + Incident Response → Dashboard + Auto-label + Templates
• Continuous Improvement → Audit + Training + Compliance

        uses: github/codeql-action/analyze@v3

📄 .github/workflows/security.yml (Security Gate)
yaml
name: "Security Gate"

on:
  pull_request:
    branches: [ "main" ]

permissions:
  contents: read
  security-events: write
  pull-requests: write

jobs:
  security-gate:
    runs-on: ubuntu-latest
    needs: [ ci, codeql, secret-scan, dependency-review ]
    steps:
      - name: Aggregate Security Results
        run: |
          echo "## Security Gate Summary" >> $`GITHUB_STEP_SUMMARY
          echo "- CI Status: `${{ needs.ci.result }}" >> $`GITHUB_STEP_SUMMARY
          echo "- CodeQL Status: `${{ needs.codeql.result }}" >> $`GITHUB_STEP_SUMMARY
          echo "- Secret Scan Status: `${{ needs.secret-scan.result }}" >> $`GITHUB_STEP_SUMMARY
          echo "- Dependency Review Status: `${{ needs['dependency-review'].result }}" >> $`GITHUB_STEP_SUMMARY
      - name: Enforce Merge Protection
        if: `${{ needs.ci.result != 'success' || needs.codeql.result != 'success' || needs['dependency-review'].result != 'success' }}
        run: |
          echo "Security checks failed. Merging is blocked."
          exit 1


📄 .github/workflows/auto-label-security.yml
yaml
name: "Auto Label Security Issues"

on:
  issues:
    types: [opened, edited]

permissions:
  issues: write

jobs:
  auto-label:
    runs-on: ubuntu-latest
    steps:
      - name: Apply Security Label
        uses: actions/github-script@v7
        with:
          script: |
            const keywords = ["security", "vulnerability", "exploit", "leak", "XSS", "SQLi"];
            const title = context.payload.issue.title.toLowerCase();
            const body = context.payload.issue.body.toLowerCase();
            if (keywords.some(word => title.includes(word) || body.includes(word))) {
              await github.rest.issues.addLabels({
                issue_number: context.payload.issue.number,
                owner: context.repo.owner,
                repo: context.repo.repo,
                labels: ["security"]
              });
            }

# Installing GitHub Copilot CLI Learn how to install Copilot CLI so that you can use Copilot directly from the command line. To find out about Copilot CLI before you install it, see [About GitHub Copilot CLI](/en/copilot/concepts/agents/copilot-cli/about-copilot-cli). ## Prerequisites * **An active GitHub Copilot subscription**. See [Copilot plans](https://github.com/features/copilot/plans?ref_product=copilot\&ref_type=engagement\&ref_style=text). * (On Windows) **PowerShell** v6 or higher If you have access to GitHub Copilot via your organization or enterprise, you cannot use Copilot CLI if your organization owner or enterprise administrator has disabled it in the organization or enterprise settings. See [Managing policies and features for GitHub Copilot in your organization](/en/copilot/how-tos/administer-copilot/manage-for-organization/manage-policies). ## Installing or updating Copilot CLI You can install Copilot CLI using WinGet (Windows), Homebrew (macOS and Linux), npm (all platforms), or an install script (macOS and Linux). ### Installing with npm (all platforms) Prerequisite: Node.js 22 or later. ```shell copy npm install -g @github/copilot ``` > \[!NOTE] > If you have `ignore-scripts=true` in your `~/.npmrc` file, you must use the command: > > ```shell copy > npm_config_ignore_scripts=false npm install -g @github/copilot > ``` To install the prerelease version: ```shell copy npm install -g @github/copilot@prerelease ``` ### Installing with WinGet (Windows) ```powershell copy winget install GitHub.Copilot ``` To install the prerelease version: ```powershell copy winget install GitHub.Copilot.Prerelease ``` ### Installing with Homebrew (macOS and Linux) ```shell copy brew install --cask copilot-cli ``` To install the prerelease version: ```shell copy brew install --cask copilot-cli@prerelease ``` ### Installing with the install script (macOS and Linux) ```shell copy curl -fsSL https://gh.io/copilot-install | bash ``` Or: ```shell copy wget -qO- https://gh.io/copilot-install | bash ``` To run as root and install to `/usr/local/bin`, use `| sudo bash`. To install to a custom directory, set the `PREFIX` environment variable. It defaults to `/usr/local` when run as root or `$HOME/.local` when run as a non-root user. To install a specific version, set the `VERSION` environment variable. It defaults to the latest version. For example, to install version `v0.0.369` to a custom directory: ```shell copy curl -fsSL https://gh.io/copilot-install | VERSION="v0.0.369" PREFIX="$HOME/custom" bash ``` ### Download from GitHub.com You can download the executables directly from [the `copilot-cli` repository](https://github.com/github/copilot-cli/releases/). Download the executable for your platform, unpack it, and run. ## Authenticating with Copilot CLI On first launch, if you're not currently logged in to GitHub, you'll be prompted to use the `/login` slash command. Enter this command and follow the on-screen instructions to authenticate. For more information on the authentication process, see [Authenticating GitHub Copilot CLI](/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli). ### Authenticating with a personal access token You can also authenticate using a fine-grained personal access token with the "Copilot Requests" permission enabled. 1. Visit [Fine-grained personal access tokens](https://github.com/settings/personal-access-tokens/new). 2. Under **Resource owner**, select your **personal account**. Do not select an organization. The **Copilot Requests** permission is only available on user-owned fine-grained personal access tokens. 3. Under **Repository access**, select the level of access appropriate for your use case: * **Public repositories** if you only need to work with public repos. * **All repositories** if you need access across all your current and future repos. * **Only select repositories** if you want to restrict access to specific repos. 4. Under **Permissions**, select the **Account** tab. 5. Click **Add permissions** and select **Copilot Requests**. 6. Click **Generate token**. 7. Export the token in your terminal or environment configuration. Use the `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, or `GITHUB_TOKEN` environment variable (in order of precedence). ## Next steps You can now use Copilot from the command line. See [Using GitHub Copilot CLI](/en/copilot/how-tos/copilot-cli/use-copilot-cli/overview). For a list of commands for Copilot CLI, including the command to update, see [GitHub Copilot CLI command reference](/en/copilot/reference/copilot-cli-reference/cli-command-reference).

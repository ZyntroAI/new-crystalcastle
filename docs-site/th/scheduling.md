# การตั้งเวลาทำงาน

scheduler ทำงานอยู่ในโปรเซสเดียวกับ API เริ่มตอน lifespan hook ของ FastAPI
และหยุดตอนปิดระบบ

## การเปิดใช้งาน

ตั้ง `SCHEDULER_ENABLED=true` ใน `.env` ตอนบูต แอปพลิเคชันจะ:

1. สร้างหรือตรวจสอบตารางในฐานข้อมูล
2. เริ่ม scheduler พร้อม session ของฐานข้อมูล
3. สตาร์ทมัน
4. หยุดอย่างเรียบร้อยตอนปิดระบบ และคืน resource ของ engine

## การตรวจว่ามันทำงานอยู่ไหม

`GET /health` บอกได้โดยตรง:

```bash
curl -s http://localhost:8000/health
```

```json
{"status": "healthy", "scheduler_running": true}
```

ในโค้ดปัจจุบัน ฟิลด์นี้คืน `true` เสมอ ให้ถือว่าเป็นสัญญาณว่าโปรเซสยังอยู่
ไม่ใช่หลักประกันว่า loop ของ scheduler สุขภาพดี — ถ้าต้องการความแน่ใจ
ให้ดู execution log

## ข้อควรระวังในการใช้งาน

!!! note "โปรเซสเดียว"
    เพราะ scheduler อยู่ในโปรเซสเว็บ การรันหลาย worker จึงทำให้มันซ้ำซ้อน
    จะขยาย API แนวนอนได้ ควรย้ายงานตั้งเวลาไป worker แยกก่อน

- **การรีสตาร์ท** จะโหลดตารางเวลาจากฐานข้อมูลใหม่ ตารางเวลาจึงอยู่รอดข้าม deploy
- **งานที่พลาดตอนระบบล่ม** จะไม่ถูกย้อนไปรันชดเชย log จะแสดงช่วงที่หายไป
- **เขตเวลา** คือค่าที่ container รายงาน ควรกำหนด `TZ` ให้ชัดเจน
  ถ้าตารางเวลาขึ้นกับเวลาท้องถิ่น
